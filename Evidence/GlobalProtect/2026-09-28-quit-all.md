# Automatic GlobalProtect disconnect and Quit All

Authorized live testing on macOS 26.6.2 (25G83), arm64, with GlobalProtect
6.3.3-1121 and TaskScope 1.0.0 (3). The user requested automatic disconnect,
complete shutdown from Quit All, and a stable TaskScope menu-bar icon.

## Installed build

Final executable SHA-256:
`0742281ea6b2f16ac9109b258388290f8d36ad0ead32af8085048a5da59f7dc6`.

The first live build had the same disconnect implementation but still rendered
a count badge. Its executable SHA-256 was
`1c011c78cfb62ab883802011b6e356e3b24a82e7cf1be1c2dbbd54bd2fcfd4c7`.
That badge was removed after observing a remaining native-item width change.
The final build uses a constant icon and label. TaskScope was also moved to
GlobalProtect's right with macOS's Command-drag gesture, so removal of the
GlobalProtect item does not shift it. That placement survived reinstallation.

## Observations

- [Permission check](2026-09-28-quit-all/accessibility-required.json): without
  Accessibility permission, Quit All reported the requirement and left the
  connected VPN and launch jobs unchanged. Accessibility was then enabled in
  System Settings with the user's one-time macOS authentication. No credential
  was collected or stored by TaskScope.
- [Initial connected shutdown](2026-09-28-quit-all/connected-stop.json): only
  TaskScope's Quit All and its confirmation were pressed. TaskScope itself
  pressed GlobalProtect's Disconnect control. The observer recorded Connected,
  the vendor's transient Connecting label, Not Connected, then absence.
- [Restore](2026-09-28-quit-all/restore-after-stop.json): Open restored the
  session service and UI without enabling the unused system daemon or showing
  an administrator window. GlobalProtect was then connected normally for the
  final test.
- [Final installed-build shutdown](2026-09-28-quit-all/final-connected-stop.json):
  the VPN began Connected. Quit All automatically disconnected and stopped it
  in approximately 33 seconds. GlobalProtect, PanGPA, and PanGPS counts were
  all zero. Both user jobs and the system job were disabled and unloaded.
  Vendor launch plists were unchanged. No SecurityAgent administrator window
  was observed; the monitor reported no errors.
- The final TaskScope menu-bar frame was exactly `x=1025, y=4, width=34,
  height=24` before and after the connected-to-off transition.
- [Public HTTPS](2026-09-28-quit-all/public-https.json): GitHub returned HTTP
  200 after the final stop, using ordinary hostname resolution. DNS settings
  and routes were not edited. GlobalProtect was left off with TaskScope open.

## Automated validation

464 tests passed, with one opt-in test skipped and no failures. The final
icon-only change was followed by another complete successful test run and
warnings-as-errors debug build, then release packaging and installation.
Coverage and strict concurrency/actor-check test runs passed on the preceding
build with the same lifecycle code. Packaging regression tests (including
106 release-evidence cases), shell syntax checks, and diff checks passed.

Tests cover disconnect-before-disable ordering, waiting through transition
states, requiring consecutive disconnected observations, a single Disconnect
press, failed/unavailable controls and timeouts, failure without persisting new
Keep Off intent, and preserving custom-preset and URL/Shortcuts stop boundaries.

## Limits

This proves the exercised English-language client on this Mac. It does not
establish compatibility with every GlobalProtect UI, management policy,
pre-login mode, logout/reboot, or private resource. Accessibility denial,
unknown connection state, or a failed disconnect prevents the explicit full
stop. The earlier vendor DNS failure remains relevant to other sequences;
these two automatic-disconnect cycles preserved public networking. The broader
compatibility release gate remains unverified.
